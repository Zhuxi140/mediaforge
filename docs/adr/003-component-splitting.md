# ADR-003: 单体 SFC → 组件拆分 + Pinia 状态管理

**状态**: ✅ 已采纳  
**日期**: 2026-06-29  

## 背景

初始开发阶段将所有 UI（重命名、FFmpeg、字幕、弹窗）放在一个 `App.vue` 文件中，随着功能增多，该文件已达 919 行。后续需要扩展，维护成本急剧上升。

## 可选方案

1. **保持单体 SFC** — 所有逻辑和模板在 App.vue 中，通过 `v-show` 切换面板
2. **组件拆分** — 每个功能模块提取为独立 `.vue` 组件
3. **组件 + 路由** — 使用 vue-router 管理页面切换
4. **组件 + Pinia** — 拆分组件 + 状态管理

## 决策

选择方案 **4（组件拆分 + Pinia 状态管理）**。

## 理由

- 组件拆分将 919 行 → 每个组件 150-200 行，职责清晰
- Pinia 替代组件内 `ref` 管理全局状态，多组件间共享数据无需 props 层层传递
- 三个面板间共享文件选择逻辑（`SelectFiles`），Pinia store 方便统一管理
- 弹窗系统提取为 composable，保持 Promise 链调用模式
- CSS 提取到独立文件，避免重复

## 后果

- 新增功能模块只需新建组件 + store，不需修改 App.vue
- 需要额外引入 Pinia 依赖（~1KB gzip）
- 组件间通信通过 store + composable，不存在 props drilling
- 组件拆分后单文件更易测试（但当前无测试）
